別讓文件在程式碼改版後，悄悄過期。

Docsentry 從 repository 的本地證據驗證 Markdown。失效連結、過期指令、錯誤設定範例與 Action input，會在合併前被具體指出。

閱讀操作指南 查看專案 README
  • 不存取網路
  • 不執行文件命令
  • 不自動改寫文件
•••

文件不是附屬品，也是產品契約。

每當 script、設定 schema 或 GitHub Action 改變，文件的承諾可能已不成立。Docsentry 將這些承諾轉成可在 CI 執行、可定位到行列的檢查。

01

抓到失效內容

驗證本地 Markdown 連結、anchors 與資產路徑，包含解析到 repository 外的 symlink。

02

對照真實證據

文件中的 package、JSON／YAML、Action input 與鏡像文件，都與工作目錄內的實際檔案比對。

03

留下可行動結果

每個 finding 都包含規則 ID、文件位置與失敗證據；一次呈現所有可發現問題，不會 fail fast。

用三個步驟，把文件治理放進日常開發。

1. 描述需要守住的契約

以 `.docsentry.json` 選擇文件，按需加入 schema、package、Action 與雙語配對規則。

2. 在本機得到完整回饋

執行 `docsentry check`；PR 規模的變更可使用 `--changed origin/main` 聚焦受影響範圍。

3. 交給 CI 守門

把相同指令放進 GitHub Actions，讓過期文件無法隨程式碼一同合併。

DOC_LINK_MISSINGDOC_LINK_ANCHOR_MISSINGDOC_SCRIPT_UNKNOWNDOC_SCHEMA_INVALIDDOC_ACTION_INPUT_UNKNOWNDOC_PAIR_*_MISMATCH
GitHub Actions

每個 PR 都有文件的安全網。

Docsentry 是一個小介面、深實作的檢查器。`check` 專注做一件事：用 repository 內可證實的資料驗證文件，不猜測、不連網，也不改檔。

查看 CI 導入細節 
steps:
  - uses: actions/checkout@v4
  - uses: CarlLee1983/Docsentry@v0.5.0
    with:
      config: .docsentry.json
      format: sarif

讓文件的每一句話，都有本地證據支持。

從一個 README 開始，建立能隨程式碼長期維護的文件契約。
